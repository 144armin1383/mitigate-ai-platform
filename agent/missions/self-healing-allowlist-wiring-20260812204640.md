## Objective

agent/repair/allowlist_recovery.py

into MITIGATE's bounded autonomous repair lifecycle.

The Agent owns architecture inspection, implementation, tests,
validation, Git delivery, and reporting.

## Existing Foundation

The classifier is already merged and validated.

It is:

- deterministic
- pure
- side-effect-free
- provider-independent
- unable to mutate allowlists
- unable to expand deliverables
- unable to bypass repository protection

Reuse it.

## Required Runtime Behavior

When generated output proposes a path outside declared mission deliverables:

1. existing generated-file validation remains authoritative;
2. the rejected path is passed to the classifier;
3. structured repair evidence is created;
4. the NEXT bounded repair attempt receives:
   - rejected path
   - exact declared deliverables
   - classification
   - fingerprint
   - safely_repairable
   - human_approval_required
   - repeated_invalid_path
   - recovery_instruction
5. repeated equivalent invalid paths are recognized;
6. repeated ineffective repairs do not loop forever;
7. existing repair budget remains authoritative;
8. no allowlist or deliverable set is automatically expanded.

## Self-Healing Requirement

The purpose of this wiring is to eliminate the failure pattern where an
autonomous attempt repeatedly invents invalid paths and fails without useful
repair guidance.

After integration, an ordinary outside-deliverable path error should normally
be recoverable autonomously within the existing bounded repair budget.
